# Project guidance

## Scope
- Keep the backend in Go. Frontend technology may be selected independently.
- Preserve offline-first behavior: failed refreshes must not discard cached data, and cached operational data must retain source and freshness metadata.
- Do not present stale or unavailable aviation data as current. Keep official source, issue/effective time, and refresh time visible.
- AviationWeather.gov airport, METAR, and TAF lookups support worldwide ICAO identifiers. Its SIGMET feed includes U.S. domestic and international products and is cached independently; PIREPs are requested within 100 NM for the previous six hours but are primarily available in the U.S. and North Atlantic.
- The METAR panel keeps the raw AviationWeather.gov report and summarizes its `clouds`, `wxString`, and `altim` fields. Ceiling is the lowest reported BKN/OVC/VV layer; cloud bases are AGL. Treat this as a convenience decode and verify the raw report.
- The TAF panel retains raw text and renders AviationWeather.gov `fcsts` periods in UTC, ordered by `timeFrom`; source change groups and probabilities are shown without converting them into a deterministic forecast.
- The SVG SIGMET/FAA/PIREP overlay is a selectable 100/250/500 NM schematic centered on the selected airport. SIGMET and FAA TFR visibility follows the selected range; PIREP markers use only reports returned within 100 NM for the prior six hours; FAA airspace and airport/navaid reference overlays are capped at 250 NM because airspace data is fetched to 250 NM. It is not a basemap or navigation chart.
- Map layer checkboxes control only SVG visibility; source data, SIGMET/TFR details, and availability statuses remain independent of layer visibility.
- FAA ArcGIS Class Airspace is queried as GeoJSON within 250 NM of a selected location and cached with an eight-week freshness interval; its published cycle is updated every eight weeks. Coverage is U.S., Puerto Rico, and U.S. Virgin Islands only. The FAA item states data is for public use and credits FAA Aeronautical Information Services. This layer is reference-only and is not for navigation or clearances: https://services6.arcgis.com/ssFJjBXIUyZDrSYZ/ArcGIS/rest/services/Class_Airspace/FeatureServer
- FAA Graphic TFRs provides a public current TFR location GeoJSON layer (max 300 returned polygons) through `https://tfr.faa.gov/geoserver/TFR/ows`; the app caches successful responses for 15 minutes and stale responses on disk for fallback. FAA publishes per-feature title, NOTAM key, and last-modified time; human-readable validity dates may occur in the title but are not structured and the app does not parse them into active/future/expired status. The map lists at most 20 nearby FAA locations, with polygon count and list count reported separately. FAA publishes no guaranteed update cadence. The overlay is U.S.-focused and a supplemental reference only; verify current NOTAMs directly with FAA before flight.
- Once the user saves the global OurAirports directory, the airport search supports offline name, ICAO, IATA, and local-identifier matches; selecting a result can show only the cached reference record without live weather.
- Saved FAA procedure and VFR PDFs appear in the offline chart library on the home screen, without requiring an airport lookup. Browser storage may be evicted; verify each chart's current edition before use.
- Users can import official regional chart PDFs (up to 50 MiB each) with source and edition metadata into browser IndexedDB for offline access. Imports are browser-local, may be evicted, and are not verified or refreshed by FP; users must respect provider terms and verify currency.
- Users can explicitly request persistent browser storage for the app's offline cache, saved charts, briefings, and local reference data. Grant is browser/device-controlled and protects against automatic eviction only; users can still clear storage, so keep source/edition/freshness checks.
- Offline chart packs can be assembled from the existing FAA procedure and VFR catalogs by selecting charts and downloading them sequentially to this browser. The manager reports transfer progress, supports cancellation, and displays browser storage usage; downloaded PDFs stay in the device chart library until removed.
- The PDF service-worker cache returns the last saved device copy on offline network failure or non-success HTTP responses; fallback responses carry `X-FP-Offline-Cache: true`.
- FAA procedures, VFR charts, and NOTAM search are U.S.-specific. International regional resources link selected airport countries to official sources: Canada NAV CANADA CFPS, Mexico SENEAM, Brazil AISWEB, Argentina ANAC, Chile DGAC, Ecuador DGAC IFIS, Suriname CADSUR AIS, Ghana GCAA, South Africa ATNS File2Fly, Spain ENAIRE/ICARO, France SIA SOFIA-Briefing, Finland Fintraffic, Norway Avinor IPPC, Germany DFS AIS, Netherlands LVNL, Italy ENAV, UK NATS AIS, Qatar AIM, UAE GCAA, Saudi SANS, Iran AIS, Japan SWIM, India AAI OFPL, Malaysia CAAM eAIP, Indonesia AirNav AIS, Singapore CAAS, Australia NAIPS, and New Zealand IFIS. These are external links, not in-app feeds or cached data; access rules and publication cadence differ by provider. Argentina's summaries are reference-only, Singapore's public list is monthly, and Australia's automated extraction/redistribution requires written authorization. Other countries can use the State AIS/AIM directory. AIP:Aero and OpenFlightMaps provide limited third-party chart access, not integrated global charts. ICAO's global NOTAM portal reports 12-hour collection and is reference-only; EAD Basic is not connected to operational data.
- Additional official country portals: AirNav Ireland publishes a current NOTAM PIB; Kenya KCAA provides online PIB/NOTAM access after a request; Thailand AEROTHAI offers NOTAM/PIB services with possible registration; Tanzania TCAA provides an informational search sourced from its Daily List of Valid NOTAMs. These remain external links, not integrated/cached feeds; check the provider's access requirements and verify validity before flight.
- Additional South American links: CORPAC Peru's NOTAM service requires user credentials requested from AIS; Paraguay DINAC publishes lists of valid NOTAMs by year. These remain external resources; verify issue time, scope, and current validity before flight.
- Sweden LFV AROWeb provides NOTAM/PIB access; Austria's Austro Control Homebriefing provides route, area, and aerodrome PIBs with possible registration; Switzerland's skybriefing by skyguide AIM offers tailored NOTAM briefings. These are external portals, not integrated/cached feeds; verify access, issue time, and briefing scope.
- Poland PANSA Integrated Web Briefing provides tailored PIBs; Denmark Naviair Briefing shows active Danish FIR NOTAMs and SNOWTAMs; Greece publishes a valid-NOTAM list and directs PIB retrieval through AIS/ARO or EAD. These external resources are not integrated/cached by FP; confirm current issue time, scope, and access.
- South Korea's official AIM has valid-NOTAM search and PIB tools; the Philippines CAAP AIS portal searches active NOTAMs by ICAO location, number, and text; Hong Kong AIS publishes Series A/C NOTAM and SNOWTAM with a last-updated time. These are external, not cached by FP; validate scope and currency. CAAF Fiji's AIM page located in this review links AIC documents but no public live NOTAM/PIB service, so Fiji retains the State AIS/AIM directory fallback rather than an unverified direct link.
- Uganda CAA AIM AviWeb offers NOTAM/SNOWTAM/ASHTAM PIB self-briefing and requires sign-in. Nigeria's NAMA AIS material located in this review points to AIS products and purchasing, not a verified public live feed; no public live Mozambique source was verified. Those countries keep the general State AIS/AIM directory fallback.
- Namibia NCAA's official NOTAM page publishes a downloadable bulletin and instructs operators to monitor the site or register for IBS self-briefing. Its bulletin is an uncontrolled copy, not a route-specific PIB; check the update time and current operational briefing.
- Botswana CAAB publishes month-stamped Series A/B/C NOTAM lists on its official site. The lists are not route-specific PIBs or continuously refreshed; verify issue/validity dates and obtain a current operational briefing.
- Algeria's official AIS page publishes monthly Series A/B NOTAM summary lists. These dated lists are not tailored route PIBs; check the latest issue date and every notice's validity, and obtain current operational information from AIS.
- ASECNA's official NOTAM consultation portal provides BNI, FIR, country, and aerodrome filters for Benin, Burkina Faso, Cameroon, Central African Republic, Comoros/Mayotte, Congo, Côte d'Ivoire, Gabon, Gambia, Guinea-Bissau, Equatorial Guinea, Madagascar, Mali, Mauritania, Niger, Réunion, Senegal, Chad, and Togo. It is a shared external search, not integrated or cached by FP; select the applicable scope and verify the current issue/validity.
- User-pasted NOTAM/PIB briefings can be saved in local IndexedDB with the source name and source-stated issue/effective time; the local save time is separate. FP does not fetch, validate, upload, or refresh these copies. Browser storage can be cleared or evicted, and the current official source must be checked before flight; save only material allowed by its provider.
- Users can save 3–4 character airport lookup shortcuts locally; saved shortcuts open live lookup with fallback to that device's cached briefing or airport reference. The shortcut does not cache additional data and does not indicate data currency.
- Confirm data access and redistribution terms before adding a provider.

## Engineering
- Prefer the Go standard library until a concrete requirement warrants a dependency.
- Keep provider integrations and HTTP handlers small, testable packages.
- Use context cancellation and bounded timeouts for network operations.
- Add behavior-focused tests for API contracts, stale/cache behavior, and provider parsing.
- Run `make check` before submitting changes. Run `make build-all` for desktop cross-builds, `make build-android-apk` and `make android-test` for Android, and `make build-ios` for iOS when their toolchains are available.
- Never commit credentials, downloaded aviation datasets, generated binaries, or local environment files.

## Platform builds
- Desktop Go builds target macOS, Linux, and Windows on amd64 and arm64 where supported by Go.
- Android APK packaging uses the checked-in Gradle wrapper, Go Mobile bridge, and Android SDK; see `android/README.md`.
- iOS app packaging uses the Go Mobile framework and Xcode project; see `ios/README.md`.
